How the numbers are calculated

Loading

  • Files are read by this browser tab only. Each file is matched to its page by its column headers (PR files also need L1–L4 in the name).
  • Loading a file again replaces the earlier copy of the same kind: the same funds file type, the same PR level, or the same Stipends, MFH Duty or DTS report. Loading your first file clears the demo data.
  • Headers match regardless of case, spaces or underscores. Personal identifier columns (such as SSN) are skipped without being read. #REF! and other error cells count as blank.

Status of Funds

  • Total Expenditure (commitment_amt_cum) and Disbursement (disbursement_amt_cum) are the export's cumulative amounts, sign-flipped (× −1) because the export carries them negative. A funds export needs both columns.
  • Obligation is calculated: Obligation = Total Expenditure − Disbursement (on the raw export: disbursement − commitment). obligation_amt_cum is not read. Spent = Obligation + Disbursement = Total Expenditure.
  • TDP and AFP come only from the funding file (Fiscal Year, Account, TDP, AFP), per Account. Functional Areas roll up to Accounts (with their Sag and MDEP) through the Account Key. Commitment items sharing a description in the Commitment Item Key are added together.
  • Balance = TDP − Total Expenditure (= TDP − Obligation − Disbursement). Straight-line pace = TDP × fiscal month ÷ 12 (October = 1). The page opens on the current fiscal year (1 October starts the next) whenever it has lines, otherwise the latest earlier year.
  • Accounts: % expended = Total Expenditure ÷ TDP. Pace compares it with the share of the fiscal year elapsed (days since 1 October): within ±10% is on pace, above is over, below is under. Commitment items are measured by Total Expenditure.

PR Tracker

  • The level comes from the file name: L3.xlsx = Level 3. Columns read: Cardholder Name (shown as First Last), Purchase requisition (PR Number), Merchant / Description (Merchant), Short Text (Description), Total Value.
  • Rows with the same PR number in one level are one PR; each row is a separate line item. Its Total Value is always the sum of its rows, and its Description is the Short Text of the row with the highest Total Value (the first one on a tie).
  • A PR found in more than one level file is shown once, at the highest level.
  • G1 Cardholder Key (optional): Cardholder, Display Name. Only listed cardholders count; names match on normalized first and last name, ignoring case and middle names. Display Name is used when provided. Any Type column is ignored. This key is separate from Aviation's.

Spend Plans

  • Planned = the spend plan: one row per Account with planned dollars for October … September, used as entered. It is always for the current fiscal year (1 October starts the next) unless the file has a Fiscal Year column. Month headers can be full names, abbreviations or dates; the header row is found automatically; blank and Total rows are skipped. A new spend plan replaces the earlier one. Plan accounts match Status of Funds accounts by name, ignoring case and extra spaces; plan accounts not found are listed here, and accounts with spending but no plan show “no plan”.
  • The page opens on the current fiscal year whenever it has a plan or actuals. (A long-format spend plan loaded with Status of Funds — Fiscal Year, Account, Fiscal Month, Planned Amount — is also read when no spend plan is uploaded here.)
  • Actual = Total Expenditure per Account and fiscal month, counted exactly as on Status of Funds (sign-flipped, Account Key). Each line's cumulative-to-date amount counts once, in its fiscal month; Cumulative is the running total from October, so September equals the year's Total Expenditure. Actuals show only through the latest month that has lines.
  • Variance % = (Actual − Planned) ÷ Planned. Up to ±5% is green, over 5% up to 10% yellow, over 10% red. An account is off plan when its to-date variance is outside ±5%.

Funeral Honors and ESGR

  • Account selection: names containing “Funeral Honors” or “ESGR”, ignoring case, after the G1 Account Key is applied. Spend is Total Expenditure, with TDP/AFP from the G1 funding file. Monthly amounts count each SOF line once in its fiscal month; cumulative is the running total from October.
  • Stipends: counts per Status as entered, by date of service. MFH Duty: duties by date performed; status matches ignoring case (Not started = red, Calendar submitted = amber, Pay submitted = green). Other statuses are retained and shown in grey.
  • DTS: only Approved date, Last name, First name, TANUM, Departure Date, Location/Destination and Total Obligation are read. Name = First Last in proper case. Obligation by month uses the Approved date; rows without an approved date remain in the table and totals. Repeat TANUMs stay in the report and are counted only in the drawer.
  • G1 data lives only in this tab or your G1 saved HTML. No localStorage or IndexedDB is used. G1 keys, funding, templates and saved block (g1Saved) are entirely separate from Aviation.
